A machine learning system that estimates a person's stress level (Low / Medium / High) from
two signals they already produce while typing: **how** they type (keystroke timing, pauses,
corrections, mouse and app-switching behaviour) and **what** they type (sentiment and
vocabulary). No wearables, no surveys.

## Datasets

| Dataset | Modality | Source | Script |
|---|---|---|---|
| Dreaddit | Text | Public, Turcan and McKeown (2019) | `run_midterm.py`, `run_text.py` |
| Kaggle "Stress Detection by Keystroke, App and Mouse Changes" | Typing | Kaggle | `run_midterm.py`, `run_typing.py` |
| SWELL-KW (Koldijk et al., 2014) | Typing / interaction | Open on DANS, CC BY-NC-SA 4.0 (see `data/README.md`) | `run_swell.py` |
| EmoSurv (Maalej and Kallel, 2020) | Both, **paired**; emotion labels | [IEEE DataPort](https://doi.org/10.21227/eae6-pk42), research use, no redistribution | `run_emosurv.py` |
| Own collected sessions | Both, **paired** | `collector/typing_collector.html` | `run_paired.py` |

We found no dataset released as paired typing and text labelled for stress. EmoSurv pairs
them under emotion labels. SWELL-KW comes closest for stress: its raw logs (`python -m dataio.swell_raw`) record every key and timestamp, so both
can be rebuilt, which `run_swell_paired.py` does. The collector adds what those logs lack:
key-hold times, self-reported labels per block and conversational text.

## Collecting your own data

Open `collector/typing_collector.html` in a browser (works offline; see
[`docs/Data_Collection_Protocol.md`](docs/Data_Collection_Protocol.md)). Each participant
does four blocks:

| Block | Condition | Task |
|---|---|---|
| 1 | Relaxed | Copy a short passage, no timer |
| 2 | Relaxed | Chat: answer 4 everyday questions, no timer |
| 3 | Time pressure | Copy a matched passage in 75 s |
| 4 | Time pressure | Chat: 4 more questions, 30 s per answer |

They rate their stress after each block. The questions come from one neutral pool and the
passages are matched, both randomly assigned to conditions, so only the time pressure differs.
Every chat answer becomes its own sample. Put the downloaded `sessions_*.csv` and
`keystrokes_*.csv` in `data/own/` and run `python run_paired.py` (or `run_final.py`).

Participant data is git-ignored. It contains raw keystrokes and typed text, so it should not
be committed to any repository.

## Evaluation

Accuracy, macro precision, macro recall, macro F1 and the majority-class baseline for every
model. Macro averages matter because the classes are imbalanced and accuracy alone hides
majority-class prediction.

Wherever participants are identifiable (SWELL-KW, own data) the test data is **whole
held-out participants**: a random split would let the model recognise people instead of
stress. On own data the models see only an explicit allow-list of inputs; condition, timing
limits, counts and self-ratings never reach them. Reasons for every choice are in
[`docs/reports/Decision_Log.md`](docs/reports/Decision_Log.md).

## Known limitations

- The Kaggle typing dataset has two participants and masked keys, so it cannot generalise
  across people and cannot support the vocabulary stream.
- Dreaddit is binary (stress / no stress) and Reddit text may not transfer to other typing
  contexts; `run_paired.py` measures that transfer on our own answers.
- Labels are self-reported (own data) or condition-based (SWELL-KW), each with its own bias.
- On the paired data of both SWELL-KW and EmoSurv, fusion shows no measurable gain over the
  better single modality.
- EmoSurv's labels are emotions, not stress.
- On a single burst, typing is at chance on unseen people, and both the demo and the extension
  say so. The significant typing scores need a whole work block and the person's own typing.
- The extension uses the classical text model (0.761), not the transformers, and because that
  model is binary a burst with enough words is never labelled Medium.

## What actually happens when you run it

The experiment scripts are command-line programs. They print progress in the terminal and
save results as files (CSVs, Markdown reports, PNG charts) in `outputs/`. No window opens.

Three things run in a browser:

- `collector/typing_collector.html`: the data-collection tool. Double-click it; no server needed.
- The demo: run `python app/server.py`, then open `http://127.0.0.1:8765`. It runs only on your
  computer and stores nothing.
- The Chrome extension (`extension/`, see its README): load the folder in Chrome, with no server
  or Python. It gives a live LOW / MED / HIGH badge while you type on any website, and can suggest
  a break.

No internet connection is needed after setup, except for the optional transformer comparison,
which downloads model weights once.
