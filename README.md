A machine learning system that estimates a person's stress level (Low / Medium / High) from
two signals they already produce while typing: **how** they type (keystroke timing, pauses,
corrections, mouse and app-switching behaviour) and **what** they type (sentiment and
vocabulary). No wearables, no surveys.

## Quick start

```bash
pip install -r requirements.txt
python -c "import nltk; nltk.download('vader_lexicon')"

# smoke test, needs no data (never quote these numbers, the signal is planted)
python run_typing.py --source synthetic
python run_text.py   --source synthetic

# real run: place datasets in data/ first (see data/README.md)
python run_midterm.py
```

`run_midterm.py` grid-searches all three classifiers on every configuration and writes
`outputs/midterm_results.csv`, `outputs/midterm_report.md`, confusion matrices, feature
importances and `outputs/cross_user_generalisation.csv`. Trained `.joblib` models are
git-ignored and are regenerated by that run.

## Datasets

| Dataset | Modality | Source |
|---|---|---|
| Dreaddit | Text | Public, Turcan and McKeown (2019) |
| Kaggle "Stress Detection by Keystroke, App and Mouse Changes" | Typing | Kaggle |
| SWELL-KW | Typing / interaction | Radboud University, requires registration |
| Own collected sessions | Both, paired | `collector/typing_collector.html` |

No public dataset pairs keystroke dynamics with typed text labelled for stress. That gap is
why the collector exists.

## Collecting your own data

Open `collector/typing_collector.html` in a browser (works offline). Each participant does four
blocks, relaxed then time-pressured, each with a copy task and a free-writing task, and rates
their stress after each. They download `sessions_*.csv` and `keystrokes_*.csv`; put them in
`data/own/` and load with `loaders.load_own_sessions()` / `loaders.load_own_keystrokes()`.

Participant data is git-ignored. It contains raw keystrokes and typed text, so it should not
be committed to any repository.

## Metrics

Accuracy, macro precision, macro recall, macro F1, cross-validated macro F1, and the
majority-class baseline for every model. Macro averages matter here because the classes are
imbalanced and accuracy alone hides majority-class prediction.

## Known limitations

- The typing dataset has two participants and masked keys, so it cannot generalise across
  people and cannot support the vocabulary stream.
- Dreaddit is binary (stress / no stress) and Reddit text may not transfer to other typing contexts.
- Labels are self-reported and therefore subjective.
- Fusion is unvalidated until paired data exists.

## What actually happens when you run it

**Nothing opens a webpage or a window.** These are command-line scripts. You run
them in a terminal, they print progress to that same terminal, and they save
their results as files (CSVs and PNG images) inside `outputs/`. That's it.

Step by step, running `python run_midterm.py`:

1. Python reads the CSV/TSV files out of `data/` (already included in this
   folder — nothing to download).
2. It converts raw keystroke events and raw text into numeric features (speed,
   pauses, sentiment scores, etc.) — this happens in memory, no file is created
   for it.
3. It trains 12 models total (3 algorithms x 4 configurations) and evaluates
   each on held-out test data. You'll see each one print its accuracy and F1
   score live in the terminal as it finishes.
4. It writes everything to `outputs/`:
   - `midterm_results.csv` — every model's scores, open in Excel or VS Code
   - `midterm_report.md` — the same results as readable text
   - nine `confusion_*.png` images — open these directly, they're plain images
   - several `feature_importance_*.csv` files
   - `cross_user_generalisation.csv`
   - twelve `.joblib` files — the trained models themselves, saved to disk
5. The terminal prints a final summary table, then the script ends. The
   terminal prompt returns and you can type the next command.

No internet connection is needed to run it — the datasets are already inside
`data/`. Internet is only needed once, for the `pip install` and the NLTK
download in setup.

The only thing in this whole project that opens in a browser is
`collector/typing_collector.html` — that's the separate tool for collecting new
data from volunteers, not for training or running the model. Double-click it or
open it via `File → Open` in a browser and it works standalone.
